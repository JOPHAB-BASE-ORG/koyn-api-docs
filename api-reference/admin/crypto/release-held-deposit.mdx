title: "Release Held Deposit"
api: "POST /console/crypto/deposits/held/{id}/release"
---

## How it works

Sends a held deposit back through the normal deposit pipeline. **Every safety check runs again**, so if the underlying cause has not been fixed (e.g. the user still has no USDT wallet on that address) it is simply held again rather than credited. Only `held` deposits can be released. Requires the `deposits.manage` console ability, and writes an admin activity-log entry.

<ParamField path="id" type="integer" required>
  The held deposit (webhook event) id.
</ParamField>
<ParamField body="note" type="string">
  Optional reviewer note, max 1000 characters.
</ParamField>

A `status` of `failed` in the response means the deposit has been requeued; the job then takes it to `completed` (credited), `pending` (awaiting confirmations), or `held` again (still unsafe).
