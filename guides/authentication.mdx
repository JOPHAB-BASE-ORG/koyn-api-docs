---
title: "Authentication"
description: "How tokens are issued and sent to the Koyn API"
---

The Koyn API uses Laravel Sanctum bearer tokens. Two separate login flows issue tokens for two separate audiences.

| Audience | Login endpoint | Used by |
| --- | --- | --- |
| App users | `POST /login`, `POST /login/pin`, `POST /login/biometric` | The Koyn mobile app |
| Staff | `POST /console/login` | The admin console |

## Sending the token

Add the token to every authenticated request:

```http
Authorization: Bearer YOUR_TOKEN
Accept: application/json
```

Staff tokens only work on `/console/*` routes and user tokens only work on app routes. Use [Token check](/api-reference/mobile/authentication/token-check-request) to confirm a stored token is still valid.

## Client version header

Send an `X-Client-Version` header carrying the app's semantic version, for example `2.0.2`, on every request.

<Warning>
  In production this is a hard gate. A request with a missing header, or a version lower than the minimum the backend enforces, is rejected before it reaches the route and returns `404` with the message `Your app version is outdated. Please upgrade to the latest version.` Outside production the header is not enforced. A `404` carrying that exact message is the version gate, not a missing resource.
</Warning>

## Transaction PIN

Money-moving endpoints such as wallet withdrawals and bill purchases require the user's transaction PIN in the request body in addition to the bearer token. See [PIN management](/api-reference/mobile/pin-management/create-pin).

## Logging out

`POST /logout` revokes the current token. Deleting a user or suspending them from the console also invalidates their tokens.
